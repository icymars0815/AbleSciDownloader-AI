# Zotero CLI 联动

Zotero 有两个作用：下载前查询本地库存，下载并核对通过后归档书目和 PDF。

```text
kytdl zotero status --json
kytdl zotero find 10.1234/example --json
kytdl zotero on --collection "目标分类" --confirmed
```

`on` 默认先展示规则，只有用户了解并同意两个作用后才带 `--confirmed`。已开启时不反复询问；改变目标分类前说明。`status` 和 `find` 只读，不创建文献或修改已有条目。

库存读取依赖运行中的 Zotero 和 Local API；归档使用 Connector 接口。查询成功不能证明写入成功。本机读取、写入和云端 API 的授权不同，不打印密钥、不转发端口、不直接读数据库，也不在本地接口失败时自动转用云端接口。

`find` 的 `not_found` 才表示本次个人库查询范围内没有命中。`unavailable` 表示未知，不能当作没有库存。当前 `has_pdf` 表示附件记录存在，`local_pdf_verified:false` 表示尚未检查本机附件文件；群组库不在当前查询范围内。

待处理队列遇到连接故障时合并提醒一次，恢复后清除过时提醒。AI 应说明“库存尚未核实”，询问先连接后继续还是本次跳过查询。现有联动是可选功能，故障不会自动撤销已授权的求助；该提示并不是“库存未核实禁止花分”的硬门槛。不要用全局关闭联动代替仅跳过某批次的查询。

推荐顺序：按 DOI 查库存 → 复用或获取缺失全文 → MD 软件核对 → 疑难交 AI → 写入前再次查重 → 归档 → 回读确认。首次验证或故障排查时，应核实条目 DOI、附件关联和文件哈希，而不是只看写入 HTTP 成功码。

当前限制：本地 PDF 可用性回读、库存全文复用、给已有条目补附件、自动写入回读及群组库配置尚未全部实现。归档失败不能伪装成下载失败；条目创建而附件失败时不应盲目重复创建条目。真实归档流程应先做小批验证。
